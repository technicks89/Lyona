One installed system on the XPS, from one image (`new13`), checked on
2026-11-11. The validation is assembled from the ARM6-02 to ARM6-05 runs on
that machine plus a final set of checks over SSH (10.0.1.154) on the same
installed system; it is not a single uninterrupted run from a freshly written
stick.

## Found

- The CPU frequency governor is `performance` (the kernel default here,
  `CONFIG_CPU_FREQ_DEFAULT_GOV_PERFORMANCE`), so the 12 cores sit at 3.4 GHz
  when idle. Measured 2026-11-11 on battery, display at full brightness, idle
  desktop, 60 s each (battery `POWER_NOW`, ramping as the gauge settles):
  `schedutil` 1.6 to 3.2 W (mean about 2.5 W), average clock 1.8 to 3.2 GHz;
  `performance` 4.1 to 5.7 W (mean about 4.9 W), 3.4 GHz. One run each,
  `performance` second. The Snapdragon install step now sets `schedutil`
  (`/etc/tmpfiles.d/90-lyona-cpufreq.conf`); not yet tested through an install
  and a reboot.
- The `gkr-pam: unable to locate daemon control file` lines at each LightDM
  login mean the GNOME keyring daemon is not started by the PAM stack. It is a
  warning only, and an existing x86_64 behavior was not compared.
