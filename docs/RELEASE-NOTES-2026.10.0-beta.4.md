# lyona 2026.10.0-beta.4

Fifth beta of the Arch Linux line. This is a **pre-release**: the ISO
workflow publishes every release with `--prerelease`, and a beta is never
promoted to Latest.

The install image now installs GRUB instead of systemd-boot, so lyona
installs on machines with a legacy BIOS as well as UEFI ones, with the CyberRe
boot menu theme (#235). `CHANGELOG.md` has the complete list.

## What is in this beta

### GRUB on legacy BIOS and UEFI

- **The wizard installs on a legacy BIOS.** It used to refuse any machine that
  booted without UEFI, because systemd-boot is UEFI-only.
  - **On UEFI,** GRUB goes in the firmware's fallback path,
    `EFI/BOOT/BOOTX64.EFI`, on an EFI system partition at `/boot`. Firmware
    that ignores the boot entries other systems write, Apple's among it, still
    boots it.
  - **On a legacy BIOS,** the disk is MBR, with an ext4 `/boot`.
  - **`/boot` is never encrypted,** as GRUB reads the kernels from it. With
    LUKS, only the root partition is encrypted.
  - **The summary** says which: `Boot: UEFI (GRUB)` or
    `Boot: legacy BIOS (GRUB)`.
- **The boot menu uses the CyberRe theme.**
- **`linux-cachyos` boots by default.** It is the menu's first entry
  (`GRUB_TOP_LEVEL`); the stock Arch kernel stays in the menu as the fallback.
  `lyona-cachyos install-kernel --make-default` sets this under GRUB too.
- **Size and time:**
  - the installed system is about 45 MiB larger;
  - GRUB itself adds about a second before its 5-second menu;
  - the install image does not grow.
- **Only the bootloader changes.** Arch, and so lyona, still uses systemd as
  its init system.

### Fixed

- **The GRUB theme reaches the menu on UEFI.** `lyona-grub-theme` and
  `lyona-cachyos` looked for `/boot/grub` as your user, but a UEFI `/boot` is
  the EFI system partition, which Arch mounts readable by root only. The menu
  was then never regenerated with the theme. They now look as root. This also
  affected existing UEFI installs that boot with GRUB from `/boot`.

## Installing from the image

1. Check the image (`docs/src/install.md`), write it to a USB stick, and boot
   it, with UEFI or a legacy BIOS.
   - **On a Mac,** hold Option at startup and choose **EFI Boot**. The other
     entry for the stick (often shown as "Windows") boots it in legacy mode,
     which works too, but EFI is the better fit for a Mac.
2. Run `lyona-install`, answer its questions, and confirm its summary.
3. When it finishes, read its notes, press Enter, and leave the stick in until
   the screen goes dark.

## Upgrading from 2026.10.0-beta.3

- **Your bootloader is not changed.** An existing install keeps the bootloader
  it has. Moving one from systemd-boot to GRUB means reinstalling from the
  image.
- **With `lyona-update`,** or from a checkout with `git pull` and
  `./install.sh`, as for beta.3.
- **Existing installs that boot with GRUB** get the CyberRe theme from
  `./install.sh` (or `sudo lyona-grub-theme apply CyberRe`), now also on UEFI.

## Qualification status

**Not tested on real hardware,** the 2012 MacBook Air included. On the build
host (Arch with the CachyOS repositories, x86_64):
- **The full suite** (`scripts/run-tests`) passed on the GRUB change before it
  was merged.
- **In QEMU/KVM,** from an image built from the GRUB branch (4 GiB, a 30 GiB
  virtio disk, btrfs, no LUKS, no NVIDIA):
  - **Legacy BIOS (SeaBIOS):** installed with no manual help and nothing on the
    closing screen. It boots the CyberRe menu, then `linux-cachyos`.
  - **UEFI (OVMF):** installed, but the theme step skipped the menu: the bug
    fixed above. With the menu regenerated by hand, as the fix now does, it
    boots the CyberRe menu, then `linux-cachyos`.

**Boot time, measured from reset in the VM:**

| Firmware | Firmware and GRUB, to the menu | Menu | Login screen or desktop | Kernel and userspace |
| --- | --- | --- | --- | --- |
| Legacy BIOS | 2.1 s | about 5.3 s | 11.6 s | 3.98 s |
| UEFI | 3.2 s, about 1 s of it GRUB | about 6.3 s | 13.7 s | 3.90 s |

**Not tested yet:**
- **A UEFI install from an image with the fix,** to see the theme applied
  without help.
- **Real hardware,** LUKS on legacy BIOS, ext4, and the NVIDIA drivers under
  GRUB.

Two tests are known to fail now and then without a fault: System Health under
Xvfb ("Control Center popup did not open") and the appearance inventory. Both
print what they saw when they fail.
